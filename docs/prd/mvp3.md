# DDD IOS2 - MVP2+3 PRD : 장소 선정 ~ 확정 플로우

## 0. 개요

MVP1에서 **날짜가 확정된 모임**을 대상으로, 모임원 출발지를 기반으로 중간 지역을 산출하고 장소를 추천·투표·확정하기까지의 전체 플로우.

- 선행: 날짜 확정 완료 (MVP1, `docs/prd/mvp1.md`)
- MVP2: 중간지점 역 후보 산출 (`docs/prd/mvp2.md`) — 본 문서에 통합
- MVP3: 장소 추천 → 담기 → 투표 → 자동 확정

> 사용자에게 노출되는 단어는 모두 "모임" 기준. 호스트/구성원 역할 정의는 MVP1을 따른다.

## 1. 프로세스 오버뷰

```
[날짜 확정]
   │  호스트 "장소 정하기"
   ▼
[중간 지역 지하철역 3개 산출]  ──┐
   ▼                            │ FC-8
[3개 역 반경 장소 점수화 → 상위 15개 추천] ─┘
   ▼
[장소 후보 리스트 탐색 및 담기]  ── FC-9

   ▼

   ▼

   │  전원 투표 완료 / 투표 마감일 도래
   ▼

```

### 상태 모델 (참고용)

> 아래 enum/명칭은 흐름 이해를 위한 참고이며, 실제 명세는 RE/RA 단계에서 확정한다.

| 상태축 | 값 | 의미 |
| --- | --- | --- |
| `locationStatus` | `BEFORE` | 장소 정하기 시작 전 (날짜만 확정) |
|  | `RECOMMENDED` | 중간지역·추천 15개 산출 완료, 담기 진행 중 (FC-9) |

|  | `CONFIRMED` | 장소 확정 완료 (FC-13) |

  - 장소 선정 전 = `BEFORE` / 선정 중 = `RECOMMENDED`·`VOTING` / 선정 완료 = `CONFIRMED`

## 2. 단계별 기능 상세 명세

### FC-8. 중간 지역 산출 및 장소 추천

날짜 확정 직후, 호스트가 "장소 정하기"를 시작하면 모임원 출발지를 기준으로 중간 지역을 찾고 맞춤 장소를 추천한다.

**전제 조건**

- `locationStatus = BEFORE` 인 모임에서 호스트가 시작
- 참여(ATTEND / LATE) 상태 구성원 전원이 기본 출발지를 보유 (회원가입 시 필수 등록이므로 통상 항상 충족)

**처리 순서**

| 단계 | 행위자 | 내용 |
| --- | --- | --- |
| 1. 시작 | 호스트 | "장소 정하기" 버튼 클릭 |
| 2. 참여자 스냅샷 | 시스템 | 현재 ATTEND/LATE 구성원의 기본 출발지 좌표를 모임 참여자 스냅샷으로 고정 |
| 3. 중간지점 계산 | 시스템 | 참여자 좌표의 기하학적 중심으로부터 접근성 좋은 **지하철역 최대 3개**(rank 1~3) 산출 |
| 4. 장소 추천 | 시스템 | 3개 역 반경 내 장소를, 모임 생성 시 선택한 옵션(테마/분위기/카테고리 등)으로 **스코어링 → 상위 15개** 선정 |
| 5. 역 귀속 태깅 | 시스템 | 추천된 각 장소를 가장 가까운(또는 소속) 역에 귀속시켜, FC-9 역 탭 필터의 기준으로 사용 |
| 6. 상태 전이 | 시스템 | `locationStatus`: BEFORE → RECOMMENDED |

**추천 알고리즘 (참고)**

- 입력: 3개 역, 모임 옵션(테마 태그 / 분위기 / 카테고리), 장소 마스터(`place`)의 옵션·태그 데이터
- 산정: 옵션 매칭 점수 산출 후 내림차순 정렬 → 상위 15개
- 결과는 각 장소가 어느 역에 귀속되는지 함께 보관 (역별 개수는 균등 분배가 아닌 점수순 결과)

**에러 / 엣지 처리**

| 상황 | 처리 |
| --- | --- |
| 호스트 아닌 구성원이 시작 시도 | 403 |
| 이미 시작된 상태(`RECOMMENDED` 이상)에서 재시작 | 400 |
| 출발지 미등록 참여자 존재 | 400 (출발지 등록 안내 후 중단) |
| 중간지점 반경 내 역이 없음 | 400 |
| 추천 후보가 15개 미만 | 가능한 개수만 추천 / 0개일 때 처리는 §5 미결 |

### FC-9. 장소 후보 리스트 탐색 및 담기

추천된 15개 장소 중, 모임원들이 실제 투표에 올릴 후보를 각자 '담는' 단계.

- 범위 제외: 장소 검색 / 호스트 단독 장소 선정 / (지도 뷰는 9-3 상세에서만)
- 표시 규칙: 데이터가 없는 항목·카테고리는 미노출

#### 9-1. 장소 후보 리스트 뷰

| 항목 | 명세 |
| --- | --- |
| 모임원 담기 현황 | 모임원별 장소 담기 완료 여부 표시. 완료한 모임원 프로필은 체크 이미지로 변경. |
| 지역(역) 선택 | 현재 선택된 지역(역명) 표시. 역 선택 시 **해당 역에 귀속된 장소 후보만** 노출. |
| 카테고리 | 카테고리별 추천 장소 확인. 후보에 없는 카테고리는 미노출.<br>카페 / 디저트 / 한식 / 중식 / 일식 / 양식 / 분식 / 아시아 음식 / 뷔페 / 주점 / 기타 |
| 필터 | 예약 가능 / 주차 가능. 선택 시 해제 전까지 카테고리·역 이동해도 유지. |
| 정렬 기준 | 추천 알고리즘 스코어 내림차순 |
| 카드 구성 | 상호명, 카테고리, 도로명 주소, 분위기 태그(최대 3개), 유저 출발지 기준 거리, [+] 버튼<br>[+] 터치 시 투표 후보로 추가, 재탭 시 취소 |
| 하단 CTA | 후보 1개 이상 추가 상태에서만 '투표 시작하기' 활성화 |
| 로딩 | 스켈레톤 UI |

#### 9-2. 장소 담기 완료 정의 및 투표 전환 조건

**"장소 담기 완료"의 정의**

- 한 모임원이 투표 후보를 **1개 이상 담으면** 그 모임원은 '담기 완료'로 간주(프로필 체크). 별도 완료 버튼 없음.
- 마감 전까지 담기/취소 자유. 단, 후보가 0개가 되면 다시 '미완료'로 돌아간다.

**투표 전환 조건** — 아래 중 하나라도 충족 시 즉시 `VOTING` 으로 전환

| 조건 | 처리 방식 | 알림 |
| --- | --- | --- |
| 전원 담기 완료 (모든 모임원이 ≥1 담음) | 즉시 투표 전환 | 전체: "모든 모임원이 장소 후보를 선정했어요. 투표가 시작됩니다!" |
| 담기 마감일 도래 (날짜 확정 +3일, 23:59:59) | 미완료 모임원 있어도 자동 전환 | 전체: "장소 후보 선정이 완료됐어요. 투표가 시작됩니다!" |
| 호스트 '투표 생성하기' 탭 (후보 ≥1) | 마감 전이어도 즉시 전환 | 전체: "장소 후보 선정이 완료됐어요. 투표가 시작됩니다!" |

| 그 외 상황 | 처리 |
| --- | --- |
| 마감일 도래 후 담기 화면 접근 | 담기 불가. "장소 후보 선정이 마감되었습니다" 안내 후 투표 화면으로 이동 |
| 마감 도래 시 후보 0개(아무도 안 담음) | §5 미결 2 |

#### 9-3. 장소 상세

각 장소 후보 터치 시 노출되는 상세. 지도 위 바텀시트 형태.

| 항목 | 명세 |
| --- | --- |
| 진입 | 지도 위 장소 핀 탭 or 리스트 카드 터치 |
| 지도 영역 | 추천 장소 핀 목록 표시. 카테고리별 아이콘·색상 구분. |
| 핀 탭 | 해당 장소 상세가 하단 시트로 노출(지도 유지) |
| 함께 담기 N | 지도 우측 하단 '함께 담기 N' — N은 해당 장소를 담은 모임원 수 |
| 거리·카테고리 | 유저 출발지 기준 거리 + 카테고리 텍스트 |
| 영업시간 | 휴무 여부, 평일/주말 영업시간 |
| 주소 | 도로명 + 지번, 각 우측 복사 아이콘 |
| 좌측 CTA | '장소담기' → 투표 후보 추가. 이미 담았으면 '담기 취소' |
| 우측 CTA | '자세히보기' → 네이버지도 딥링크 (`nmap://place?id={place_id}`) |

> **데이터 소스 (FC-8 보강, V32)**: 상세 필드는 `GET /api/v1/places?ids=` 응답으로 제공.
> - 영업시간/휴무 = `businessHours`/`holiday` (표시용 원문 텍스트)
> - 주소 = `roadAddress`(도로명) + `address`(지번)
> - 자세히보기 = `naverUrl`(https URL) 또는 `placeId`로 딥링크 조립
> - **거리·함께 담기 N은 이 상세 API 스코프 제외** (거리=리소스 부담, 함께담기 N=담기현황 API 책임)

#### 9-4. 장소 함께 담기

모임원별 담기 현황 확인 페이지.

| 항목 | 명세 |
| --- | --- |
| 타이틀 | '장소 함께 담기' |
| 모임원 담기 현황 | 상단 프로필 목록. 완료한 모임원 하단 체크 아이콘. 미완료는 체크 없음. |
| 카테고리 탭 | 전체 / 카테고리별 필터. 후보에 없는 카테고리 미노출. |
| 카드 구성 | 카테고리 아이콘, 상호명, 거리, 주소, 분위기 태그(최대 3개), [+] 버튼 |
| 마감 임박 토스트 | 마감 1일 전: "장소 선정일이 1일 남았어요" (빨간색, X로 닫기) |
| 진행 중 토스트 | "장소 선정은 3일동안 진행돼요" (초록색, X로 닫기) |
| '투표 생성하기' 버튼 | 호스트에게만 하단 고정 노출 |
| ─ 비활성화 | 아무도 담지 않은 상태 |
| ─ 활성화 | 모임원 중 1명 이상 담기 완료 (호스트 포함 누구든) |
| ─ 탭 시 | 마감 전이어도 즉시 투표 전환, 전체 알림 발송 |
| 로딩 | 스켈레톤 UI |

### FC-11. 투표 생성 및 마감일 설정

장소 후보가 모여 투표가 시작될 때, 투표 종료 시점을 설정한다.

| 항목 | 상세 명세 |
| --- | --- |
| 마감일 프리셋 | 투표 시작일 기준 **+1일 / +3일 / +7일** 중 선택. 마감 시각은 선택일 **23:59:59** 자동 설정 |
| 유효성 검사 | 1) 투표 마감일은 **약속 날짜(모임일) 이전**<br>2) 투표 마감일은 **투표 시작일 이후** |
| 에러 처리 | 조건 위반 시: "투표 마감일은 약속 날짜 이전으로 설정해 주세요" |

> 마감일/호스트 조기 시작으로 자동 전환된 경우의 마감일 기본값은 §5 미결 3.

### FC-12. 장소 투표 진행

선정된 후보 장소를 대상으로 최종 장소를 결정하는 익명 투표.

| 항목 | 상세 명세 |
| --- | --- |
| 리스트 정렬 | 투표 전: 상호명 가나다순 / 투표 후: 득표수 높은 순 실시간 정렬 |
| 투표 수 제한 | 1인당 최대 = **후보 수의 50% 이하**(내림). 단 **최소 1개 보장** (예: 후보 6 → 3, 후보 3 → 1, 후보 1 → 1) |
| 투표 완료 정의 | 한 모임원이 **1개 이상 투표하면** '투표 완료'로 간주. 마감 전까지 투표 추가/취소 가능(후보 0개가 되면 다시 미완료). |
| 익명성 | 누가 어디에 투표했는지 블라인드. 호스트에게는 **투표 완료 여부만** 공개 |
| 이동 부담 표시 | 후보별 모임원의 **출발지↔장소 이동 경로·환승 횟수·총 소요 시간** 제공. 이동 시간이 가장 긴 구성원은 별도 식별(UI 빨간색 강조) |
| 전환 조건 | 아래 중 하나라도 충족 시 즉시 `CONFIRMED`(FC-13)로 전환<br>1) 전원 투표 완료<br>2) 투표 마감일 도래 (미투표자 기권 처리) |

**이동 부담 데이터 산출 방향** *(검토 중 — §5 미결 4)*

- 가정: 모임원은 **지하철로만 이동**한다고 단순화.
- 방식: 공공데이터(역간 소요시간/환승 정보)를 확보해 지하철 노선을 **그래프**로 구성하고, 출발지 최근접 역 ↔ 장소 최근접 역 간 **최단 경로(소요시간·환승)** 를 서버에서 계산.
- 계산 시점: 투표 시작 시점에 (참여자 × 후보) 경로를 1회 계산·저장(스냅샷)하는 방향 우선 검토. *(실시간 외부 길찾기 API 연동은 비용/지연으로 보류)*

### FC-13. 장소 자동 확정

투표 종료 시점에 시스템이 논쟁 없이 1위 장소를 자동 확정한다.

| 항목 | 상세 명세 |
| --- | --- |
| 자동 순위 로직 | 투표 종료 시점 데이터로 아래 우선순위에 따라 1위 확정<br>**1순위:** 득표 수 최다<br>**2순위(동점):** 모임원 전체 **이동 시간 합산 최소**<br>**3순위(동점):** 모임원 전체 **환승 횟수 합산 최소**<br>**4순위(동점):** 후보 **등록(담긴) 순서가 가장 빠른** 장소 |

## 6. 비기능 요구사항

- 중간지점·추천 계산은 PostGIS 네이티브 쿼리로 처리(서버 메모리 연산 최소화)
- 출발지 좌표는 장소 정하기 시작 시점 스냅샷으로 고정 (이후 출발지 변경 무관)
- 투표 현황은 실시간(또는 준실시간) 반영
- 상태 전환·마감 처리 및 푸시 알림은 스케줄러로 자동 발송
