# DDD IOS2 - MVP2 PRD

## 1. 개요

MVP1에서 확정된 날짜를 기반으로, 모임 참여자들의 출발지를 기하학적으로 분석해 **중간지점 지하철역 후보 3개**를 자동 추천하는 장소 선정 플로우.

---

## 2. 기능 요구사항

### FC-midpoint: 장소 선정 — 중간지점 역 후보 추천

**전제 조건**

- 날짜 투표가 확정된 모임(`locationStatus = BEFORE`)에서 호스트가 시작
- 참여(ATTEND / LATE) 상태인 구성원 전원이 기본 출발지를 등록해야 시작 가능

**장소 선정 단계 시작 (호스트)**

| 단계 | 행위자 | 내용 |
| --- | --- | --- |
| 1. 시작 | 호스트 | "장소 정하기" 버튼 클릭 |
| 2. 참여자 스냅샷 | 시스템 자동 | 현재 ATTEND/LATE 구성원의 기본 출발지 좌표를 `meeting_participant`에 저장 |
| 3. 중간지점 계산 | 시스템 자동 | 참여자 좌표의 기하학적 중심으로부터 2km 이내 지하철역 후보 3개 계산 |
| 4. 후보 저장 | 시스템 자동 | `midpoint_station_candidate`에 rank 1~3 저장 |
| 5. 상태 전이 | 시스템 자동 | `meeting.locationStatus`: BEFORE → IN_PROGRESS |

**후보 조회 (구성원)**

- 장소 선정 시작 후 rank 1~3 역 목록 조회
- 표시 정보: 역명, 호선(복수 호선 콤마 구분), 중간지점으로부터의 거리(km)

**에러 처리**

| 상황 | 처리 |
| --- | --- |
| 호스트 아닌 구성원이 시작 시도 | 403 |
| 이미 시작된 상태에서 재시작 시도 | 400 |
| 출발지 미등록 참여자가 있는 경우 | 400 (전체 중단, 출발지 먼저 등록 안내) |
| 중간지점 2km 내 역이 없는 경우 | 400 |

---

## 3. 데이터 모델

| 테이블 | 설명 |
| --- | --- |
| `meeting_participant` | 장소 선정 시작 시점의 참여자 출발지 스냅샷 |
| `subway_station` | 전국 지하철역 좌표·호선 데이터 (PostGIS geography) |
| `midpoint_station_candidate` | 계산된 중간지점 역 후보 (rank 1~3) |

---

## 4. 비기능 요구사항

- 중간지점 계산은 PostGIS 네이티브 쿼리로 처리 (서버 메모리 연산 없음)
- 출발지 좌표는 장소 선정 시작 시점에 스냅샷으로 고정 (이후 출발지 변경 무관)

---

## 5. MVP2 범위 제외 (추후 대응)

- 후보 역에서 최종 장소 확정 플로우
- 장소 수동 입력 / 재계산 기능
- 역 주변 식당·카페 추천 연동
