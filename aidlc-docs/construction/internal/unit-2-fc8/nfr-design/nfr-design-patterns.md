# U2 — NFR Design Patterns (경량)

## 성능 패턴
- 반경 사다리는 SQL CTE 내부에서 가능한 한 처리(역 검색)하거나 최대 3회 반복 호출(장소 검색) — 후보가 ~2천건 규모라 N+1/캐시 불필요
- 스코어링은 애플리케이션 메모리에서 처리(순수 함수), DB 왕복 없음

## 신뢰성 패턴
- 트랜잭션 경계: `PlaceSelectionService.startLocationPhase` 전체가 하나의 `@Transactional` — 가드 검증 실패/추천 0건 시 예외로 전체 롤백(부분 저장 없음)
- 명시적 에러코드로 실패 원인 구분(가드/참여자/역/장소)

## 보안 패턴
- 기존 Spring Security + JWT, GroupMemberRole 체크 패턴 재사용. 신규 패턴 없음

## 확장 패턴
- 현 규모(데이터 ~2천건, 저빈도 호출)에서는 캐시/큐/서킷브레이커 불필요로 판단. 추후 place 데이터가 수만 건 이상으로 늘어나면 반경검색 결과 캐싱 고려(범위 외, 기록만)
