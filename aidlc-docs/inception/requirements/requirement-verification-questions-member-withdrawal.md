## Q15. 탈퇴 시점 파기 범위 (Q1·Q2·Q3 통합 재확인)

**권장안**: 탈퇴 요청 시 아래를 **한 트랜잭션에서 즉시** 처리

```
[member 테이블 — 뼈대만 남김]
  status            = WITHDRAWN
  deleted_at        = now()
  nickname          = NULL
  email             = NULL
  profile_image_url = NULL
  social_user_id    = 'withdrawn_' + UUID   ← 난수 치환 (NOT NULL 제약 유지)
  → 남는 것: id, social_provider, status, deleted_at, created_at (식별 불가)

[물리 삭제]
  refresh_token       DELETE  ← 방침 "인증 토큰은 탈퇴 시 파기"
  device_token        DELETE  ← 방침 "탈퇴 처리 시까지"
  departure_place     DELETE  ← 방침 "탈퇴 처리 완료 시까지"
  terms_agreement     DELETE  ← 방침 "탈퇴 처리 완료 시까지"

[유지 — 타 이용자 권리 보호 근거]
  group_member         (닉네임은 member가 NULL이라 자동으로 '알 수 없음')
  meeting_participant  (행 유지, 단 아래 필드는 NULL)
  date_vote_record / meeting_place_pick / meeting_place_vote  (집계 정합성)

[유지하되 개인정보 필드 NULL]
  meeting_participant.latitude / longitude          ← 위치정보
  meeting_participant.departure_label / place_name / address  ← 출발지 정보

[물리 삭제 — 출발지 파생]
  meeting_travel_burden (탈퇴자 행)  ← 소요시간·환승·station_path(출발역 노출)
```

- A) 권장안 그대로 확정
- B) 일부 변경 — 변경할 항목 기재
- X) 기타

[Answer]: A

> 참고 — `terms_agreement`까지 지우면 "이 사람이 약관에 동의했었다"는 증빙이 사라집니다. 무료 서비스이고 결제·계약 기록이 없어 전자상거래법상 보존 의무는 없으므로 방침대로 삭제가 맞습니다. 만약 증빙을 남기고 싶다면 방침에 "부정 이용 방지·분쟁 대응 목적 N개월 보관"을 **먼저 추가**해야 합니다.

## Q19. 소셜 연동 해제(Revoke) — 용어 설명 및 결정 (Q8 답변에 대한 회신)

**Revoke가 뭔가요?**
카카오/네이버/애플에게 "이 사용자와 우리 앱의 연결을 끊어달라"고 **우리 서버가 소셜 제공자 서버에 API를 호출**하는 것입니다.

- 호출 안 하면: 우리 DB에서는 탈퇴됐지만, 사용자의 카카오 계정 "연결된 서비스" 목록에는 반가워가 남아 있습니다.
- 애플의 경우 `Sign in with Apple` 사용 앱은 계정 삭제 시 **REST API로 토큰을 revoke하라**고 가이드라인에 명시돼 있습니다.

**우리 구조상의 문제**: 현재 `AuthService`는 소셜 토큰으로 사용자 정보만 조회하고 **토큰을 저장하지 않습니다.** 따라서 revoke를 하려면 탈퇴 요청 시 클라이언트가 **소셜 토큰을 다시 보내줘야** 합니다 → API 계약 변경 + 클라이언트 작업 필요.

- A) **MVP는 호출 안 함** — 단, iOS 심사 제출 전 별도 사이클로 Apple revoke 추가 (백로그 등록)
- B) **지금 Apple revoke만 포함** — `DELETE /api/v1/members/me` 에 `appleAuthorizationCode` 선택 필드 추가
- C) 3사 모두 지금 포함
- X) 기타

[Answer]:B

> 권장: **A**. 앱 심사 일정이 임박했다면 B.
