# Requirements — FC-12 보완: 이동경로(station path) 스냅샷 저장

> 2026-06-25. 기존 FC-12(이동 부담 / 친구들 거리보기) 확장. 새 FC 아님 — fc12 폴더 갱신.

## 배경 / 문제
- 현재 `meeting_travel_burden` 스냅샷은 **소요시간(seconds) + 환승수(transfers)** 만 저장.
- "친구들 거리보기"에서 **지도에 실제 이동 경로(거쳐가는 역)** 를 그릴 데이터가 없음.
- `SubwayGraph.dijkstra`는 비용만 계산하고 **경로 복원(prev 추적)이 불가능한 구조**.

## 목표
- 투표 시작(세션 생성) 시 이동부담 계산과 **동일한 다익스트라 1회**로 **출발역→도착역 경로**를 함께 산출.
- 경로 = `[{stationId, latitude, longitude}, ...]` **출발지부터 목적지까지 순서 있는 리스트**.
- `meeting_travel_burden` 한 행에 **반정규화(JSONB 단일 컬럼)** 로 저장. 별도 경로 테이블 생성 금지(행 폭증 회피).
- "친구들 거리보기" 조회 시 **재계산 없이 스냅샷에서 경로까지** 반환.

## 기능 요구사항
- R-P1: 이동부담 스냅샷 계산 시, 각 (참여자, 후보) 조합에 대해 **경로(역 순서 + 좌표)** 를 함께 저장한다.
- R-P2: 경로는 출발역(참여자 최근접역) → 도착역(후보 최근접역) 순서로 정렬된 리스트다.
- R-P3: 도달 불가(경로 없음)이면 경로는 **빈 리스트**, 기존대로 seconds=무한대 처리.
- R-P4: 친구들 거리보기 API 응답의 멤버별 항목에 `path`(역 좌표 리스트)를 포함한다.
- R-P5: 좌표는 `subway_station` 테이블 기준. 경로 복원된 stationId들의 좌표를 배치 조회해 채운다.

## 비기능 / 제약
- 별도 테이블 금지 → `meeting_travel_burden`에 JSONB 컬럼 1개 추가 (의도된 반정규화).
- 경로 데이터는 "조회 시 통째로 읽고 통째로 쓴다" — 부분수정/조인/필터 없음 → JSONB 적합.
- Cloud Run 다중 인스턴스 안전 (기존과 동일: 시작 시 1회 계산 후 DB 스냅샷).
- 기존 seconds/transfers 계산 결과는 **불변** (회귀 없음).

## 영향 범위
- `SubwayGraph.dijkstra` 반환 구조 변경 (호출부: PlaceVoteService 1곳).
- `subway_station` 좌표 배치 조회 메서드 신규.
- `meeting_travel_burden` 스키마(V29) + 도메인/엔티티 + 응답 DTO.

## 결정사항
1. 경로 저장 위치 = **기존 테이블 JSONB 컬럼** (별도 테이블 X) — 사용자 결정(반정규화).
2. 경로 좌표 = `{stationId, latitude, longitude}` 순서 리스트.
3. dijkstra는 비용+경로 모두 반환하도록 변경 (별도 메서드 분리 아님 — 단일 계산 재사용).
4. 친구들 거리보기(R9) 응답에만 경로 노출. 투표 현황(getVoteStatus)에는 경로 미포함(요약만 유지).
