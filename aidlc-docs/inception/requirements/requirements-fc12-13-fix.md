## 기능 요구사항

### R1. 투표 후보 = 담긴 장소 (담기 기준 정합화) 🔴
- 투표 현황 조회·투표 제출·이동부담 계산의 후보 소스를 **추천 15개 → 담긴 장소(`meeting_place_pick`)** 로 변경.
- 최대 투표수 = `max(1, 담긴후보수 / 2)` (50% 내림, 최소 1 보장).
- **수용 기준**: 투표 화면에 담긴 후보(+R2 백필분)만 노출. 50% 제한이 담긴 후보 수 기준으로 동작.

### R2. 후보 최소 3개 백필 🔴
- 투표 시작 시점(수동·자동·마감 모든 경로)에 담긴 후보가 3개 미만이면, **추천 장소(`recommendation`)를 순위(rank) 오름차순으로, 이미 담긴 장소를 제외하고** 3개가 될 때까지 채운다.
- 추천 총량이 3개 미만이면 가능한 만큼만.
- 백필된 장소는 일반 후보와 동일(투표·이동부담·확정 대상).
- **수용 기준**: 담긴 후보 0개여도 투표 정상 시작, 확정까지 멈춤 없이 진행. 마감 스케줄러 자동전환 경로에서도 동일 적용.
- **구현 메모**: 백필 결과를 어떻게 영속화할지는 설계 단계 결정 — 권장은 백필분도 `meeting_place_pick`(또는 후보 스냅샷)에 시스템 주체로 적재해 후속 조회/확정 로직 일관성 확보.

### R3. 투표 제출 placeId 검증 🔴
- `submitVote`에서 제출된 모든 placeId가 **현재 후보 집합(담김+백필)** 에 속하는지 검증. 위반 시 400.

### R4. 멤버별 투표 참여 현황 (전원 공개) 🟠
> 🔄 2026-06-24 결정 변경: 호스트 전용 → **모든 구성원 공개**. (별도 화면 "장소 투표 멤버별 참여 현황" 요구)
- 투표 현황 조회 시 **모든 호출자(호스트/일반 구성원 무관)** 에게 구성원별 완료 여부(`완료/미완료`) 리스트 제공.
- 단 **누가 어디에 투표했는지(투표 대상)는 전원 비공개**(익명 유지). 공개 범위는 "완료/미완료" 여부에 한정.
- 리스트 기준 집합 = 모임 활성 참여자(ABSENT 제외). 이름은 닉네임 사용.
- 기존 FC-9 "담기 현황"(`getPickStatus`)이 멤버별 담기 여부를 전원 공개하는 패턴과 정합.
- **수용 기준**: 호스트·일반 구성원 응답 모두에 `memberStatuses[]`(멤버별 완료여부) 포함. 투표 대상 정보는 어떤 응답에도 미포함.

### R5. 투표 현황 정렬 🟡
- 투표 전(내가 0표): 상호명 가나다순. 투표 후: 득표수 내림차순.
- **수용 기준**: 정렬 기준이 응답 순서에 반영.

### R6. 수동 확정 엔드포인트 🟠
- 호스트가 투표 진행 중(`VOTING`) 직접 확정 가능한 API 추가. 현재 1위 산출 로직(R8)으로 확정 → `CONFIRMED` 전환.
- 권한: 호스트 전용. 상태: `VOTING`에서만 허용.
- 자동 확정(전원완료/마감)과 결과 동일.

### R7. 1~3위 순위 산출·저장 + 확정 결과 확장 🟠
- 확정 시 1위만이 아니라 **1~3위 순위를 산출**. 후보가 3개 미만이면 후보 수만큼.
- 확정 결과 응답에 각 후보 `rank` 포함. 4위 이하 노출 정책은 클라이언트 결정 가능하도록 rank 제공.
- **수용 기준**: `place-result` 응답에 rank·정렬 포함, 후보<3 시 그 수만큼만 순위 부여.

### R9. 친구들 거리보기 — 단일 장소 이동부담 조회 API 🟠
> 🔄 2026-06-24 결정 변경: MVP 제외 → **포함**. 장소 상세 화면 "친구들 거리보기" 버튼용.
- 신규 API: 특정 `placeId` 하나에 대한 **모임원별 소요시간/환승 횟수** 목록 조회.
- 응답: 멤버별 `{memberId, name(닉네임), seconds, transfers, isLongest}` + 장소 요약.
- 데이터 소스 = 투표 시작 시 저장된 `meeting_travel_burden` 스냅샷(신규 계산 없음).
- 권한: 모임 구성원. 스냅샷 없으면(그래프 미로드) 빈 목록.
- **수용 기준**: 상세 화면에서 단일 호출로 그 장소의 친구별 거리·환승 표시 가능.

### R8. 자동 순위/동점 처리 정합화 🟠
- 순위 비교 기준(내림차순 1위부터):
  1. 득표수 최다
  2. 동점 → 이동시간 합산 최소 (`travel_burden.seconds` 합)
  3. 동점 → 환승수 합산 최소 (`travel_burden.transfers` 합)
  4. 동점 → **그 장소를 최초로 담은 시각(`pickedAt` 최소값) 오름차순** ← 현재 미정렬 버그 수정
- 이동부담 스냅샷이 없을 때(그래프 미로드 등): 2·3 기준은 동일값(0) 처리되어 4번으로 귀결.
- 전원 기권(전원 0표): 4번 기준으로 1위 확정.
- **수용 기준**: 동일 비교자를 1위 선정과 1~3위 순위 산출에 공통 적용. 등록순서가 결정적(deterministic).
